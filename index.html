Who I am and what I build

I'm Ryan Kevin Omondi Konyango (瑞安), a backend engineer and computer science undergraduate in Hangzhou, originally from Zimbabwe. I design scalable backend architectures, distributed task queues, and resilient REST APIs, and I build them as modular, production-ready systems grounded in clean architecture and solid data flows.

Why I do it

I want to bridge cultures and solve real historical and social data-representation challenges through software. Technology should preserve heritage, streamline human experiences, and empower communities, whether that is a cultural preservation platform or an automated data pipeline.

How I work

I plan visually first, mapping data flows and state interactions before writing backend logic. I pair that with Docker, Redis, Celery, and automated CI/CD so what I ship is maintainable and built to scale.

Where I'm heading

Right now I'm focused on high-impact distributed systems and on expanding my footprint across global tech ecosystems, with the longer-term goal of architecting large-scale backend infrastructure.

Projects

01

Annsana

Cultural-heritage preservation platform for African communities: media archive, user workflows, and secure transactions in one modular Django system.

  • 5 Django apps
  • 7 delivery phases shipped
  • Async media pipeline. Image processing runs in Celery workers behind a Redis broker, so uploads return immediately and workers scale independently of the web tier.
  • Versioned, rate-limited API. DRF endpoints secured with OAuth2/JWT, with Redis-backed rate limiting protecting shared routes.
  • Clear boundaries. Designed the PostgreSQL schema and a modular monolith so each domain can evolve in its own app.
  • Delivery pipeline. Dockerised, with GitHub Actions CI/CD and automated tests covering the auth and rate-limiting flows.
02

Kenzim

Installable progressive web app for the Kenyan community in Zimbabwe: one platform for membership, communication, events, and a community marketplace, deployable entirely on free-tier cloud infrastructure. Built for a client.

  • design targets
  • <2 s page load on 4G
  • 95%+ availability on free tier
  • 5,000+ members of headroom
  • Installable PWA. Installs on mobile and desktop and falls back gracefully when connectivity drops.
  • Secure member management. Supabase Auth and PostgreSQL back a multi-level role hierarchy, with an administrative approval workflow for new members.
  • Community operations. Dues tracking, event registration with RSVP, news publishing, photo galleries, a member directory, a marketplace, and an interactive community map.
  • Cost-efficient by design. Runs entirely on free-tier services (Vercel, Supabase, OpenStreetMap), with a straightforward migration path to paid tiers as the community grows.

Attendance and academic-performance tracking system that predicts attendance behaviour and triggers automated alerts.
